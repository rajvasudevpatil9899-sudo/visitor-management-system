# Visitor Registration Flask Demo

## Files
- `app.py`: Flask routes, validation, automatic timestamps, demo in-memory storage, and staff checkout route.
- `templates/visitor_form.html`: visitor form.
- `templates/security_visitors.html`: demo staff visitor log and checkout action.
- `static/style.css`: responsive styling.
- `requirements.txt`: dependency.

## Run
1. Install Python 3.10+.
2. Open a terminal in this folder.
3. Run `python -m venv .venv`
4. Activate it:
   - Windows: `.venv\Scripts\activate`
   - macOS/Linux: `source .venv/bin/activate`
5. Run `pip install -r requirements.txt`
6. Run `python app.py`
7. Open `http://127.0.0.1:5000/`
8. Demo staff log: `http://127.0.0.1:5000/security/visitors`

## Important
- Date and check-in timestamp are generated by the server on submission.
- Check-out timestamp is recorded through the staff checkout route.
- This demo stores visitors in memory, so records disappear when the app restarts.
- Before deployment, use a database, configure a strong secret key, add authentication and role-based authorisation to every `/security/` route, apply CSRF protection, validate inputs, and protect personal/ID data.
- Set the correct server timezone for your institution. Timestamps include the server's timezone offset.


## Automatic visitor confirmation emails

The application sends a confirmation email to the email address entered by each visitor after their registration is saved successfully.

SMTP credentials belong to the application administrator, not to visitors:

1. Install dependencies: `pip install -r requirements.txt`.
2. Copy `.env.example` to a new file named `.env` in this project folder.
3. Open `.env` and enter the college/system Gmail address and its Google App Password.
4. Keep `.env` private. Do not upload it to GitHub or share it.
5. Restart Flask after changing `.env`.

For deployment, set the same SMTP variables in the hosting provider's environment-variable settings instead of uploading a `.env` file. The visitor only enters their own email address in the registration form.

Gmail requires 2-Step Verification and a Google App Password. Use the App Password, not the normal Gmail account password.


## Staff login and role-based access

1. Start MySQL and confirm the existing `visitor_management` database connection in `db.py`.
2. Install dependencies with `pip install -r requirements.txt`.
3. Run the application using `python app.py`.
4. Open `http://127.0.0.1:5000/setup-admin` and create the one main administrator account. This one-time setup page closes after the first administrator is created.
5. Log in at `http://127.0.0.1:5000/login`. The administrator is sent to the Admin Dashboard.
6. From the Admin Dashboard, create a separate username and password for each security guard.
7. Security guards use the same login page and are sent to the Security Dashboard. The administrator can activate or deactivate guard accounts.

The application automatically creates a `users` table in the existing `visitor_management` database. Passwords are stored as secure password hashes. The public visitor registration page remains available without staff login. Security dashboard routes require an active security account, and admin account-management routes require the administrator role. Set a strong `SECRET_KEY` environment variable before deployment.
